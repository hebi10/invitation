## Design Specificity Verdict

**부분적으로 제품에 특화됐지만 시각 언어는 아직 카테고리 교체 가능 수준입니다.**

### LLM assessment

“제작 → 공유 → 운영 → 추억 보관”이라는 카피는 실제 운영형 서비스의 차별점을 잘 담습니다. 하지만 화면은 `헤드라인 + 기능 태그 + CTA 카드 + 감성 이미지 + 기능 카드`라는 범용 SaaS 랜딩 패턴입니다. 특히 `phoneFrame`이라는 이름과 달리 실제 보이는 것은 모바일 UI가 아닌 웨딩 사진에 가까워, 공개 상태·편집·방명록 운영이라는 가장 강한 제품 자산이 시각적으로 증명되지 않습니다.

### Deterministic scan

`detect.mjs --json src/app/page.tsx`는 exit code 0, finding 0건으로 기계 규칙상 clean이었습니다. 다만 런타임 브라우저 검사에서는 자식 컴포넌트와 CSS에 걸친 체험 안내의 Esc/초점 문제, 모바일 dialog 버튼 38px, 내부 링크의 새 탭 동작, CTA 경쟁을 확인했습니다. detector false positive는 없으며, 정적 단일 파일 검사 범위를 넘어선 런타임 문제로 보는 편이 정확합니다.

### Visual overlays

사용자-visible overlay는 제공되지 않았습니다. 브라우저의 URL 보안 정책이 `javascript:` 기반 mutable injection을 차단해 preflight가 실패했으며, 제목 변경과 script 삽입 모두 발생하지 않았습니다. 대신 새 브라우저 탭에서 데스크톱 1280×720, 모바일 390×844 화면·DOM·computed layout·실제 버튼 동작을 확인했습니다.

## Overall Impression

차분하고 성실하며 기본 반응형도 안정적입니다. 다만 신규 고객, 체험 사용자, 기존 고객, 관리자가 한 히어로에서 동시에 같은 무게로 호출되어 첫 행동이 흐려지고, 운영형 서비스라는 고유한 강점이 감성 사진 뒤에 숨습니다. 가장 큰 기회는 **CTA를 역할별로 재배치하고 실제 제품 화면을 히어로의 주인공으로 만드는 것**입니다.

## What's Working

1. **제품의 실제 수명주기가 카피에 담겨 있습니다.** 제작만이 아니라 공개 기간, 방명록, 이미지 관리, 예식 후 추억 페이지까지 설명해 운영형 서비스라는 진실을 숨기지 않습니다.
2. **체험 데이터 안전 고지가 좋습니다.** 공유 데이터, 초기화 시각, 개인정보 금지를 실행 전에 보여줘 실수와 개인정보 입력을 예방합니다.
3. **기본 반응형과 시맨틱 구조가 안정적입니다.** 390px에서 가로 넘침이 없고, H1/H2 구조·목록·이미지 대체 텍스트·section labeling이 갖춰져 있습니다. 히어로 CTA 높이도 66–68px로 충분합니다.

## Priority Issues

### [P1] 첫 화면에서 사용자 역할과 CTA가 충돌함

- **왜 중요한가:** 신규 방문자에게 `직접 체험`, `샘플 보기`, `제작 문의`, `내 청첩장`, `관리자 페이지`가 한꺼번에 제시됩니다. 직접 체험과 샘플 보기는 같은 진한 녹색이라 두 개의 주 CTA가 경쟁합니다.
- **수정:** 신규 고객 기준으로 `1 primary + 1 secondary`만 남기고, 기존 고객과 관리자는 헤더의 작은 유틸리티 링크로 분리합니다. 포트폴리오 데모는 별도 영역으로 내립니다.
- **추천 명령:** `$impeccable shape`, `$impeccable distill`

### [P1] 운영형 제품의 핵심 증거가 감성 화보로 대체됨

- **왜 중요한가:** “청첩장 미리보기”라고 안내하지만 실제 화면은 꽃길 웨딩 사진으로 읽힙니다. 편집·공개 상태·방명록 관리가 보이지 않아 평범한 제작 대행처럼 보일 수 있습니다.
- **수정:** 실제 공개 청첩장 화면을 코드 기반 휴대폰 프레임에 넣고, 공개 상태 또는 편집기 화면을 작은 운영 패널로 결합합니다. 감성 이미지는 분위기용 보조 자산으로만 사용합니다.
- **추천 명령:** `$impeccable bolder`, `$impeccable layout`

### [P1] 설득 흐름이 기능 목록에서 끝남

- **왜 중요한가:** 모바일에서 약 2,735px를 스크롤한 끝에 기능 카드만 남고 다음 행동이 없습니다. 신뢰를 만든 직후의 전환 지점이 사라집니다.
- **수정:** 실제 결과 사례나 운영 화면, 확인 가능한 제작 범위·수정 가능 여부를 보여준 뒤 최종 CTA를 반복합니다. 검증할 수 없는 수치나 후기는 만들지 않습니다.
- **추천 명령:** `$impeccable shape`, `$impeccable delight`

### [P2] 모바일에서 제품 증거가 CTA 아래로 밀림

- **왜 중요한가:** 390×844에서 5개 CTA가 한 열로 쌓이고 실제 이미지 상단만 첫 화면에 걸립니다. 사용자는 제품을 보기 전에 경로를 결정해야 합니다.
- **수정:** 모바일은 제목 다음에 실제 결과 화면을 먼저 보여주고 주 CTA 1–2개만 유지합니다. 나머지는 기존 고객용 유틸리티 영역이나 하단으로 이동합니다.
- **추천 명령:** `$impeccable adapt`, `$impeccable distill`

### [P2] 체험 안내가 dialog 역할을 완성하지 못함

- **왜 중요한가:** `role="dialog"`이지만 Esc로 닫히지 않고, 열릴 때 초점이 trigger에 남으며 `aria-modal`과 초점 이동·복귀가 없습니다. 모바일 내부 버튼의 실제 높이도 38px입니다.
- **수정:** 짧은 인라인 안내로 단순화하거나 실제 modal/bottom sheet로 구현해 Esc 종료, 초점 이동·복귀, 최소 44px 터치 영역을 보장합니다.
- **추천 명령:** `$impeccable harden`, `$impeccable audit`

## Image Direction

**GPT Image 2는 핵심 개선에 필수적이지 않습니다.** 먼저 필요한 자산은 실제 공개 청첩장 화면과 실제 편집기/공개 상태 관리 화면 캡처입니다. 두 화면을 코드 기반 휴대폰·운영 패널 컴포지션으로 결합하는 편이 설득력이 큽니다.

GPT Image 2는 다음과 같은 보조 자산에만 적합합니다.

- 텍스트와 UI가 없는 맞춤형 에디토리얼 배경
- 실제 스크린샷이 놓일 여백이 충분한 한국 웨딩 스테이셔너리 장면
- 결혼식·돌잔치·생일·개업을 절제되게 은유하는 멀티 이벤트 스틸라이프

생성 이미지 안에 UI나 한글을 직접 넣지 않습니다. 제품 증거는 실제 화면으로, 분위기는 생성 이미지로 역할을 분리합니다.
