## 디자인 특이성 판정

**제품 기능 언어는 구체적이지만 시각 언어는 범용 SaaS 관리자 UI에 가깝습니다.** 청첩장 공개 상태·테마·고객 연결·노출 기간이라는 정보 모델은 제품에 맞지만, 흰 카드·블루 포인트·요약 카드·필터 툴바·표 구성은 다른 CMS에도 거의 그대로 적용될 수 있습니다. 청첩장 미니 프리뷰, 행사 생애주기, 공개 상태 타임라인처럼 제품만의 운영 맥락을 시각 구조로 드러낼 여지가 큽니다.

자동 탐지는 `src/app/admin` 전체에서 0건이었습니다(exit 0, JSON `[]`). 이는 기계적으로 탐지 가능한 금지 패턴이 없다는 뜻이지, 반응형 전환·정보 구조·오류 상태가 완성됐다는 뜻은 아닙니다. 실제로 소스 검토에서는 모바일 전용 목록이 항상 숨겨지는 문제와 조회 오류 상태 부재가 확인됐습니다. 탐지 결과에는 오탐이 없었습니다.

관리자 인증 때문에 목표 본문에 탐지 오버레이를 표시하지 못했습니다. 브라우저의 변경 가능 사전 검사도 read-only 환경 오류로 실패했으므로 사용자에게 보이는 오버레이가 있다고 주장하지 않습니다.

## 전체 인상

운영에 필요한 기능과 기본 상태 표현은 잘 갖춰져 있고 토큰 체계도 안정적입니다. 가장 큰 기회는 기능을 더하는 것이 아니라, 세 겹의 탐색 구조와 행별 제어를 줄여 “한 건을 찾고 안전하게 처리하는 흐름”을 전면에 세우는 것입니다.

인지 부하는 8개 항목 중 5개 실패로 높습니다. 페이지 유형 5개, 세부 탭 5개, 한 행의 6개 이상 작업이 각각 작업 기억의 권장 범위를 넘습니다. 시작 시 요약 카드는 통제감을 주지만 실제 작업까지 지나야 할 층이 많고, 완료 토스트는 빠르게 사라져 마무리 확신이 약합니다.

## 잘된 점

- 공개·소유권·기간·테마 상태를 배지와 텍스트로 함께 보여 색상만으로 의미를 전달하지 않습니다.
- 삭제·공개 전환·등급·테마 제거에 확인 단계와 진행 중 비활성화를 적용해 운영 실수를 예방합니다.
- URL 기반 필터 상태, 활성 탭, 필터 칩, 페이지당 개수 등 반복 운영의 기본 도구가 갖춰져 있습니다.

- **수정:** `isError/error`를 화면에 전달하고 원인 요약, 다시 시도, 캐시 데이터 유지 상태를 제공하십시오.

### [P1] 현재 위치를 설명하는 층이 너무 많습니다

- **근거:** `src/app/admin/AdminPageClient.tsx:775`, `:791`, `:793`; `src/app/admin/_components/adminPageUtils.ts:67`
- **추천 명령:** `$impeccable distill`

### [P2] 행 작업 밀도가 높고 위험 작업이 일상 작업과 붙어 있습니다

- **왜 중요한가:** 등급·디자인·공개 상태·모바일·고객 링크·삭제가 동시에 노출돼 반복 작업의 오조작과 탐색 시간이 늘어납니다.

## 사소한 관찰

- 모든 페이지 번호를 한꺼번에 렌더링해 데이터가 많아지면 선택지가 폭증합니다. 처음·끝·현재 ±2·말줄임 구조가 적합합니다.
- 로딩 스피너에 `role="status"`나 라이브 영역이 없습니다.
- 미래 카테고리 분기에 깨진 `??` 문구가 남아 있어 이후 노출 위험이 있습니다.
- 긴 이름·slug·RTL 문자열에 대한 모바일 줄바꿈 방어가 명시적이지 않습니다.
- 로그인 화면은 데스크톱에서 안정적으로 중앙 정렬되지만 `관리자 로그인` 제목의 중복과 카드 안 카드 구조가 있습니다. 모바일은 가로 넘침은 없으나 390×844에서 Google 로그인까지 보려면 세로 스크롤이 필요합니다.
