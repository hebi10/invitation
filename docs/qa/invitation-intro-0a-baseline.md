## 시각 분석

### Light
아이보리·종이 질감·명조는 청첩장 콘셉트에 적합. 다만 글자 진입, 금빛 조명 이동, 글자 퇴장, clip-path 와이프가 중첩되어 약 4.3초 후에 종료됨. 모바일 약 3.2초 와이프 화면에서 종이와 뒤의 일반 본문이 이질적으로 분할되어 보임. PC에서는 480px 중앙 종이 영역과 넓은 측면 여백이 어색하게 공존함. 개선: 텍스트 1회 등장과 부드러운 단일 종료.

### Cinema
초반 검은 화면 → 상하 셔터 이동 → 인물 사진 → 영문 레이블·이름 → 이미지 전환. 모바일 약 1~2초에 사진/문구가 온전히 보이고 이후 퇴장. PC에서는 480px 세로 인물 사진에 비해 1440px 배경의 어두운 빈 공간이 커 보임. 개선: 셔터 제거, 대표 사진 중심의 짧은 등장, 본문 표지 연결은 별도 실페이지 검증.

### Envelope
금빛 봉인, 3D 덮개 회전, 삼각형 내부에 나타나는 사진, 카드 상승을 모두 사용. 실제 클릭 후 약 0.6초의 사진 노출과 1.6초의 상승 장면은 입체 효과가 겹쳐 과장된 느낌. 작은 보조 문구도 많음. 개선: 입체 봉투/금빛 장식 대신 평면 인쇄 카드와 짧은 이동·페이드.

## 기술 위험 및 보존 범위

1. P0: 현행 WeddingIntro는 window.resize 에 complete()를 연결하여 폴더블 펼침/회전/주소창 변화에서 임의 종료할 가능성이 있으며 6/6 브라우저 재현.
2. P0: 실제 본문 대표 사진 좌표 측정/가시성 숨김/원복 로직은 미리보기에서 확인 불가. 공개 5종 진짜 URL에서 통합 QA 필요.
3. P1: 각 웨딩 디자인의 배경/타이포와 인트로가 끊김 없이 이어지는지 실제 캡처 비교 필요.
4. P2: reduced-motion, 물리 Android/iOS, TalkBack/VoiceOver는 추가 검증 대상.
5. 보존: 기존 none/light/cinema/envelope 저장 키, 세션 최초 노출, URL hash 진입 시 건너뛰기, 수동 건너뛰기, PC/Android 웹 공통 렌더러.

이번 0-A에서는 UI, Firebase 운영 데이터, 결제, 공개 URL, 앱 빌드·배포 설정을 변경하지 않음.
