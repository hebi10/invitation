# 샘플 청첩장 폴백 및 렌더링 안정화 설계

## 목표

등록된 샘플 청첩장의 저장 데이터가 비어 있거나 손상되어도 공통 샘플 데이터와 로컬 이미지를 사용해 완성된 화면을 제공한다. 사용자가 이후 실제 데이터를 입력하면 샘플 값은 즉시 대체되고 입력값이 우선 노출되어야 한다.

## 범위

- 등록된 샘플 청첩장에만 데이터 폴백을 적용한다.
- 실제 고객 청첩장에는 가짜 예식 정보나 샘플 이미지를 주입하지 않는다.
- 로맨틱 테마의 빈 일정 데이터 무한 상태 갱신을 제거한다.
- 빈 갤러리와 위치 정보가 의미 없는 빈 섹션으로 남지 않도록 한다.
- 범용 로맨틱 웨딩 표지 이미지를 생성해 프로젝트 로컬 자산으로 사용한다.

## 데이터 우선순위

필드별 우선순위는 다음과 같다.

1. 사용자가 나중에 입력하고 저장한 유효한 값
2. Firestore에 이미 저장된 유효한 값
3. 해당 slug에 등록된 소스 샘플 시드 값
4. 프로젝트 공통 샘플 기본값

빈 문자열, 공백 문자열, 유효하지 않은 날짜 숫자, 비어 있는 객체와 배열은 폴백 대상이다. `false`, 정상적인 `0`, 사용자가 의도적으로 끈 기능 값은 빈 값으로 취급하지 않는다. 배열은 실제 저장 항목이 하나라도 있으면 그대로 유지하고, 완전히 비었을 때만 샘플 배열로 보완한다.

## 서버 데이터 흐름

공개 페이지 서버 조회에서 Firestore 커스텀 설정을 읽은 뒤 등록된 샘플 시드와 필드 단위로 병합한다. 병합 결과는 렌더러에 전달하기 전에 정규화한다.

- 이름, 날짜, 예식장, 인사말, 일정, 지도, 갤러리, 계좌 정보는 유효한 저장값을 우선한다.
- 날짜의 `year`, `month`, `day`가 유효하지 않으면 샘플 날짜를 사용한다.
- 이미지 URL이 비어 있거나 샘플용 외부 이미지로 사용할 수 없는 경우 로컬 샘플 이미지를 사용한다.
- 사용자가 새 값을 저장한 다음 요청부터는 저장값이 폴백값을 대체한다.

## 이미지 자산

GPT Image 2 기반 이미지 생성 기능으로 인물 식별성이 없는 로맨틱 웨딩 아치 사진을 만든다.

- 세로형 모바일 청첩장 표지에 맞는 구도
- 부드러운 자연광, 아이보리·연분홍·그린 톤
- 텍스트, 로고, 워터마크 없음
- 신랑·신부 얼굴이 중심이 되지 않는 빈 예식 공간
- 최종 파일은 `public/images/sample-wedding-romantic.png`에 저장

정상적인 사용자 이미지가 있으면 로컬 샘플 이미지는 사용하지 않는다.

## 렌더링 안정성

로맨틱 일정 섹션은 유효한 탭이 없으면 상태 보정 effect를 실행하지 않고 바로 렌더링을 생략한다. 탭 상태 변경은 현재 탭과 다음 탭이 다를 때만 수행한다.

갤러리 이미지가 없으면 갤러리 섹션 전체를 숨긴다. 위치에 표시할 주소, 예식장, 설명, 연락처, 유효한 좌표가 모두 없으면 위치 섹션 전체를 숨긴다.

## 오류 처리

- 샘플 병합에 실패하면 기존 저장 데이터를 손상시키지 않고 현재 공개 접근 정책을 유지한다.
- 외부 이미지 실패가 페이지 로딩 완료를 막지 않아야 한다.
- 폴백 적용은 읽기 경로에서만 수행하며 Firestore 데이터를 자동 수정하지 않는다.

## 테스트

1. 비어 있는 샘플 커스텀 설정이 소스 샘플 값으로 보완되는 테스트
2. 사용자가 입력한 값이 샘플보다 우선하는 테스트
3. `false`와 기능 설정이 샘플로 덮어써지지 않는 테스트
4. 빈 일정 데이터에서 상태 갱신 루프가 발생하지 않는 테스트
5. 빈 갤러리와 위치 섹션이 숨겨지는 렌더링 계약 테스트
6. 관련 린트, 웹 타입체크, 전체 로컬 테스트
7. 모바일과 데스크톱 브라우저에서 날짜, 이미지, 섹션, 콘솔 오류 재확인

## 비범위

- 운영 Firestore 문서의 직접 수정 또는 삭제
- 고객이 입력한 정상 데이터 변경
- 청첩장 테마 전반의 디자인 개편
- 카카오톡 실제 메시지 전송
