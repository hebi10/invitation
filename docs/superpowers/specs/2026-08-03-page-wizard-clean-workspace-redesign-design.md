# 페이지 위저드 클린 워크스페이스 리디자인

## 1. 목표

`/page-wizard/`와 `/page-wizard/[slug]`를 관리자와 고객이 데스크톱·모바일에서 모두 사용할 수 있는 입력 중심 작업 화면으로 리디자인한다.

현재 화면의 크림색 배경, 명조 중심 타이포그래피, 반복되는 둥근 카드·그라데이션·그림자를 제거하고, 긴 입력 작업에서 정보 구조와 상태를 빠르게 파악할 수 있는 평면적 운영 UI로 교체한다.

이번 변경은 화면 구조와 스타일에 한정한다. 기존 입력 항목, 이벤트 유형별 문구와 단계, 검증 규칙, 저장 스키마, API, 인증·인가, 공개·초안 동작은 보존한다.

## 2. 사용자와 사용 환경

- 관리자와 연결된 고객이 동일한 편집 화면을 사용한다.
- 두 역할 모두 데스크톱과 모바일에서 전체 기능을 사용할 수 있어야 한다.
- 관리자는 여러 이벤트를 운영하면서 빠르게 상태를 파악하고 수정한다.
- 고객은 자신의 이벤트 정보를 순서대로 입력하고 누락 없이 저장한다.
- 역할에 따른 권한 차이는 기존 로직을 따르며 UI가 권한을 새로 판단하지 않는다.

## 3. 핵심 원칙

1. 입력 항목과 기능을 제거하지 않는다.
2. 이벤트 유형과 생성·수정 모드에 따라 달라지는 모든 기존 단계의 데이터·검증 키를 유지하되, 화면에서는 최대 6개 작업 영역으로 묶는다.
3. 입력과 상태 확인을 우선하고 장식은 최소화한다.
4. 오류는 현재 위치와 전체 목차에서 동시에 식별할 수 있어야 한다.
5. 데스크톱과 모바일의 정보 구조는 동일하고 배치만 반응형으로 달라진다.
6. 미리보기는 필요할 때 열며 기본 입력 공간을 침범하지 않는다.

## 4. 정보 구조

| 새 작업 영역 | 포함되는 기존 단계 | 포함 기능 |
|---|---|---|
| 1. 시작 설정 | `eventType`, `theme`, `slug` 중 현재 흐름에 존재하는 단계 | 이벤트 유형, 디자인, 상품·서비스 구성, 한글·영문 이름 또는 행사명, 페이지 주소 |
| 2. 기본 정보 | `basic` | 대표 이름, 첫 화면 문구 및 이벤트 유형별 기본 정보 전체 |
| 3. 일정과 장소 | `schedule` | 날짜, 시간, 장소명, 주소, 지도 및 교통 관련 입력 |
| 4. 인사말과 관계 정보 | `greeting` | 인사말 템플릿·직접 입력, 웨딩의 양가 가족 정보 등 이벤트 유형별 관계 정보 |
| 5. 사진과 부가 기능 | `images`, `music`, `extra` | 대표 이미지, 갤러리, 공유 이미지, 배경음악, 축의금·화환·교통·추가 안내 |
| 6. 검토 및 저장 | `final` | 공개 여부, 공유 문구, 전체 오류 검토, 초안 저장 또는 공개 |

이벤트 유형에 따라 존재하지 않는 기존 단계는 현재 `wizardSteps` 설정대로 제외한다. 빈 작업 영역은 목차에 표시하지 않는다. 생일·일반 행사·개업 등 전용 필드와 문구, 작업 영역 제목도 기존 설정과 어댑터에 맞게 바뀐다.

## 5. 화면 구조

### 5.1 데스크톱

- 상단 작업 바: 이벤트 이름, 페이지 주소 또는 신규 상태, 저장 상태, 미리보기 버튼
- 왼쪽 목차: 6개 작업 영역과 완료·확인 필요·현재 상태
- 중앙 입력 영역: 현재 작업 영역의 제목, 설명, 기존 단계별 입력 섹션
- 하단 작업 바: 이전 영역, 다음 영역, 최종 저장 또는 공개 동작
- 미리보기: 오른쪽에서 열리는 보조 패널. 닫으면 중앙 입력 영역이 원래 폭으로 복귀한다.

목차는 충분한 화면 폭에서 고정되며 중앙 입력 영역만 스크롤한다. 작은 데스크톱과 태블릿에서는 목차 폭을 줄이고 미리보기는 전체 오버레이로 전환한다.

### 5.2 모바일

- 상단: `현재 영역 / 전체 영역`, 영역 제목, 저장 상태, 목차 열기 버튼
- 본문: 한 열 입력 구조와 단계별 소제목
- 하단 고정 작업 바: 이전·다음 또는 저장 버튼
- 목차: 시트 형태로 열어 원하는 작업 영역으로 이동
- 미리보기: 전체 화면으로 열며 닫을 때 기존 입력 스크롤 위치와 포커스를 복원

고정 작업 바는 안전 영역을 고려하고 입력창이나 오류 문구를 가리지 않는다.

## 6. 시각 체계

- 모드: 작업 완료가 목적인 `Operate`
- 배경: 흰색과 중립 회색의 평면적 레이어
- 텍스트: 짙은 먹색, 보조 정보는 충분한 대비의 회색
- 강조색: 진행, 포커스, 주요 동작에만 사용하는 하나의 절제된 색상
- 글꼴: 가독성 높은 시스템 고딕 계열
- 구분: 그림자 대신 여백, 정렬, 얇은 구분선으로 계층 표현
- 모서리: 입력창과 제어 요소에 필요한 작은 반경만 사용
- 금지: 크림색 웨딩 배경, 명조 장식 제목, 장식용 그라데이션, 과도한 캡슐 버튼, 반복 카드 중첩, 장식용 그림자

페이지가 청첩장 디자인을 직접 닮기보다, 어떤 이벤트 유형도 안정적으로 편집할 수 있는 중립적인 작업 도구처럼 보여야 한다.

## 7. 컴포넌트 설계

기존 단계 컴포넌트와 상태 훅을 재사용하고 화면 셸만 재구성한다.

- `WizardWorkspace`: 전체 반응형 작업 화면
- `WizardTopBar`: 이벤트 식별 정보, 저장 상태, 미리보기 진입
- `WizardSectionNav`: 6개 작업 영역과 상태 요약
- `WizardSection`: 한 작업 영역 안에서 기존 단계 컴포넌트를 순서대로 렌더링
- `WizardSectionHeader`: 영역 제목과 간단한 안내
- `WizardPreviewPanel`: 기존 `PageWizardStepPreview`를 감싸는 데스크톱 패널·모바일 전체 화면
- `WizardActionBar`: 이전·다음·저장·공개 동작

구체적인 파일 분리는 구현 시 현재 2,000줄이 넘는 `PageWizardClient.tsx`의 책임을 더 키우지 않는 방향으로 결정한다. 데이터 로직과 표현 컴포넌트 사이의 공개 인터페이스는 현재 훅과 이벤트 핸들러를 기준으로 유지한다.

## 8. 데이터와 이동 흐름

1. `wizardSteps`에서 현재 이벤트 유형에 맞는 기존 단계를 가져온다.
2. 각 기존 단계 키를 6개 작업 영역 설정에 매핑한다.
3. 현재 작업 영역은 포함된 첫 번째 기존 단계 키를 대표 위치로 사용한다.
4. 영역 본문은 포함된 기존 단계 컴포넌트를 모두 렌더링하되 명확한 소제목으로 구분한다.
5. 다음 영역 이동 시 포함된 기존 단계 검증을 모두 실행한다.
6. 검증 실패 시 첫 오류가 있는 기존 단계 컨테이너로 이동한다. 오류 필드가 식별되면 첫 입력 제어로 포커스를 옮기고, 식별할 수 없으면 해당 단계 제목으로 포커스를 옮긴다.
7. 저장·미리보기·공개는 현재 핸들러와 데이터 모델을 그대로 사용한다.

기존 Swiper 기반 한 단계씩 이동하는 표현은 제거 대상이지만, 기존 단계 키와 검증 결과는 누락 방지와 호환성을 위해 유지한다.

## 9. 상태와 오류 처리

- 작업 영역 상태: `현재`, `완료`, `확인 필요`, `미입력`
- 저장 상태: `저장 중`, `저장됨`, `저장 실패`
- 오류는 해당 필드의 설명과 연결하고 첫 오류로 포커스를 이동한다.
- 왼쪽 또는 모바일 목차에 오류 개수를 표시하되 색상만으로 전달하지 않는다.
- 저장 실패 시 입력 상태를 유지하고 같은 위치에서 재시도할 수 있게 한다.
- 이미지 업로드 진행·실패, 권한 제한, 소유권 연결, 초기 로딩 화면도 새 시각 체계에 맞춘다.
- 최종 저장 전에는 기존 전체 검증을 실행하고 누락된 작업 영역으로 이동할 수 있는 요약을 제공한다.

## 10. 접근성과 반응형 기준

- 모든 핵심 동작은 키보드로 수행 가능해야 한다.
- 명확한 포커스 표시와 논리적인 탭 순서를 제공한다.
- 입력 라벨, 필수·선택 상태, 힌트와 오류의 관계를 보조기술이 인식할 수 있어야 한다.
- 상태는 텍스트와 아이콘 또는 형태를 함께 사용한다.
- 모바일 핵심 터치 대상은 최소 44px 높이를 유지한다.
- 브라우저 확대와 긴 한국어 문구에서도 잘림이나 가로 스크롤이 없어야 한다.
- 미리보기 패널은 열고 닫을 때 포커스를 관리한다.

## 11. 구현 범위

### 포함

- `/page-wizard/`, `/page-wizard/[slug]`의 편집 화면
- 로딩·접근 제한·소유권·오류 상태 화면
- 기존 단계 컴포넌트의 시각적 일관성 조정
- 데스크톱·태블릿·모바일 반응형 배치
- 기존 입력 및 검증 결과를 6개 작업 영역 상태로 집계하는 표시 로직

### 제외

- 저장 스키마와 마이그레이션
- API 응답 구조
- 인증·인가 정책
- 이벤트 공개 페이지 디자인
- 새로운 입력 필드 또는 상품 기능
- 관리자 대시보드의 다른 화면

## 12. 검증 계획

### 자동 검증

- 웹 타입 검사
- 웹 린트
- 기존 페이지 위저드 관련 테스트
- 고객 저장 경로와 이벤트 유형별 위저드 테스트
- Impeccable UI detector를 변경 대상에 한 번 실행

### 브라우저 검증

- 관리자 신규 생성과 기존 수정
- 연결된 고객의 기존 이벤트 수정
- 데스크톱과 모바일에서 6개 작업 영역 이동
- 모든 기존 입력 항목 존재 여부
- 필수 오류 표시와 첫 오류 이동
- 입력·이미지 업로드·미리보기·초안 저장·공개 흐름
- 저장 실패 후 입력 유지와 재시도
- 긴 문구, 작은 화면, 키보드 포커스

## 13. 완료 기준

- 기존 이벤트 유형별 입력 항목과 기능이 모두 접근 가능하다.
- 이벤트 유형과 생성·수정 모드별 모든 기존 단계의 검증이 새 작업 영역에서도 빠짐없이 실행된다.
- 저장 데이터와 공개 결과가 변경 전과 호환된다.
- 데스크톱과 모바일에서 관리자·고객 모두 전체 편집 흐름을 완료할 수 있다.
- 기존의 크림색·명조·그라데이션·반복 카드 중심 인상이 제거된다.
- 사용자는 현재 위치, 남은 오류, 저장 상태와 다음 행동을 설명 없이 파악할 수 있다.
