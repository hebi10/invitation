# 관리자 운영 콘솔 개선 설계

## 1. 배경

현재 `/admin`은 필요한 운영 기능을 대부분 제공하지만, 큰 소개형 헤더와 요약 카드, 관리 섹션, 이벤트 유형, 세부 기능 탭이 본문 위에 겹쳐 있다. 이벤트 목록의 한 행에는 등급, 디자인, 공개 상태, 모바일 편집, 고객 연결, 삭제 등 많은 작업이 동시에 노출된다.

이 구조는 기능을 발견하는 데는 도움이 되지만 관리자가 이벤트 한 건을 찾아 바로 처리하는 일상 업무에는 불필요한 탐색과 판단을 요구한다. 또한 데스크톱 표의 최소 너비는 900px이고 모바일 목록은 표시되지 않아 모바일 운영 경로가 안정적이지 않다.

## 2. 확정된 제품 방향

- 관리자의 가장 빈번한 업무는 여러 이벤트 중 한 건을 찾아 상태를 확인하고 편집 또는 공개 관리로 이동하는 것이다.
- 모바일 청첩장이 주요 이벤트 유형이지만 관리자 화면은 청첩장에 종속되지 않는다.
- 지원 이벤트 유형은 청첩장, 돌잔치, 생일, 일반 행사, 개업이다.
- 모바일 관리자는 조회, 미리보기, 공개 상태 변경과 편집 화면 이동만 수행한다.
- 이미지, 방명록, 고객 소유권, 삭제 등 복잡하거나 위험한 작업은 데스크톱 중심으로 제공한다.

## 3. 설계 목표

1. 첫 화면에서 검색과 실제 이벤트 목록을 바로 보여준다.
2. 검색 결과를 떠나지 않고 선택한 이벤트의 핵심 상태와 작업을 확인한다.
3. 이벤트 공통 정보와 유형별 기능을 분리해 새로운 이벤트 유형을 추가하기 쉽게 만든다.
4. 일상 작업과 위험 작업을 시각적·상호작용적으로 분리한다.
5. 모바일에서는 기능을 억지로 축소하지 않고 최소 운영 경로만 안정적으로 제공한다.
6. 오류, 빈 상태, 권한 상태를 실제 데이터 없음과 혼동하지 않게 한다.
7. 소개형·장식형 대시보드 표현을 줄이고 실제 운영 데이터가 화면의 중심이 되게 한다.

## 4. 비목표

- 공개 이벤트 페이지와 테마를 재설계하지 않는다.
- 이벤트 생성·편집 위저드의 단계나 저장 구조를 변경하지 않는다.
- API 응답, Firestore schema, 인증·인가 정책을 변경하지 않는다.
- 새로운 통계 또는 분석 시스템을 만들지 않는다.
- 모바일과 데스크톱의 기능 동등성을 목표로 하지 않는다.
- 초기 개선 범위에 다중 선택과 일괄 변경을 포함하지 않는다.

## 5. 사용자와 핵심 업무

### 주 사용자

여러 이벤트를 운영하는 관리자다. 반복적으로 이름, 공개 상태, 일정, 고객 연결 상태를 확인하고 필요한 편집 경로로 이동한다.

### 핵심 흐름

`이벤트 검색 → 결과 선택 → 상세 상태 확인 → 편집·미리보기·공개 상태 변경`

### 성공 기준

- 검색과 목록이 첫 화면에 노출된다.
- 이벤트를 선택하기 위해 관리 탭을 여러 번 이동하지 않는다.
- 선택 후 페이지 이동 없이 공통 상태를 확인한다.
- 편집, 미리보기, 공개 상태 변경은 상세 패널에서 바로 실행한다.
- 목록으로 돌아왔을 때 검색, 필터, 선택 위치와 스크롤이 유지된다.

## 6. 정보 구조

### 최상위 업무 영역

1. **이벤트**: 모든 이벤트 유형의 검색, 상태 확인, 편집 진입
2. **방명록**: 여러 이벤트를 가로지르는 댓글 검토와 운영
3. **고객**: 고객 계정, 연결 이벤트, 제작권 운영

기존 `페이지`, `추억`, `이미지`, `노출 기간`은 최상위 탭에서 제거한다. 이 기능은 이벤트 한 건을 선택한 뒤 관련 관리 기능으로 제공한다. 방명록은 전체 이벤트를 검토하는 최상위 업무 영역과 선택한 이벤트만 필터링해 여는 상세 진입점을 함께 제공한다.

### 이벤트 유형

청첩장, 돌잔치, 생일, 일반 행사, 개업은 서로 다른 최상위 화면이 아니라 이벤트 목록의 필터다. 기본값은 `전체 유형`이다. 특정 유형이 주요 업무여도 전체 구조는 이벤트 공통 모델을 유지한다.

### 공통 정보와 유형별 기능

모든 이벤트는 다음 공통 정보를 표시한다.

- 이벤트명
- 이벤트 유형
- 행사 일정
- 공개 상태
- 고객 연결 상태
- 최근 수정 시각
- 공개 주소
- 대표 이미지 또는 미리보기

유형별 기능은 이벤트 registry와 현재 데이터가 지원하는 항목만 노출한다. 청첩장 전용 테마, 일반 행사 참석 신청처럼 다른 유형에 없는 기능을 공통 화면에 빈 자리로 남기지 않는다.

## 7. 데스크톱 화면

### 공통 상단 바

- 서비스 또는 관리 화면명
- `이벤트`, `방명록`, `고객` 내비게이션
- 관리자 계정 메뉴와 로그아웃
- 현재 업무와 관계없는 소개 문구는 배치하지 않는다.

`Invitation Admin`, 큰 환영 제목, 반복 설명, 별도의 현재 위치 요약 카드는 제거한다.

### 이벤트 화면 헤더

- 제목: `이벤트 관리`
- 기본 작업: `새 이벤트 만들기`
- 검색창: 이벤트명과 공개 주소 검색
- 간결한 현황: 전체, 공개, 비공개, 고객 미연결 수

현황 숫자는 별도 카드가 아니라 필터 가능한 텍스트 컨트롤로 제공한다.

### 검색과 필터

항상 노출하는 필터:

- 이벤트 유형
- 공개 상태
- 고객 연결 상태
- 정렬

낮은 빈도의 조건은 `필터 더보기`에 둔다. 적용된 필터는 목록 위에 표시하고 전체 초기화를 제공한다. 검색과 필터는 URL query에 보존한다.

### 이벤트 목록

목록 열은 다음으로 제한한다.

- 이벤트명과 공개 주소
- 유형
- 행사일
- 공개 상태
- 고객 연결 상태
- 최근 수정
- 기본 작업

행 전체를 선택할 수 있다. 기본 작업은 `편집`, 보조 작업은 `미리보기`다. 등급, 테마, 고객 링크, 삭제를 모두 행 안에서 직접 조작하지 않는다.

### 상세 패널

이벤트 행을 선택하면 오른쪽 상세 패널을 연다. 목록의 검색과 스크롤은 그대로 유지한다. 넓은 화면에서는 목록과 패널을 함께 보여주고, 공간이 부족하면 패널이 목록 위에 겹쳐 열린다.

상세 패널 순서:

1. 대표 이미지 또는 이벤트 페이지 미리보기
2. 이벤트명, 유형, 일정, 공개 주소
3. 공개 상태와 노출 기간
4. 고객 연결 상태
5. 주요 작업
6. 관련 관리 기능
7. 위험 작업

주요 작업:

- 편집
- 미리보기
- 공개 또는 비공개 변경

관련 관리 기능:

- 이미지
- 추억 페이지
- 방명록
- 노출 기간
- 고객 연결

각 항목은 현재 상태나 건수를 함께 표시한다. 지원하지 않는 기능은 disabled 상태로 남기지 않고 렌더링하지 않는다.

고객 연결 해제와 이벤트 삭제는 접힌 `위험 작업` 영역 또는 더보기 메뉴에 둔다. 삭제는 영향 범위를 설명하고 취소를 기본 선택으로 제공한다.

## 8. 모바일 화면

### 지원 기능

- 검색
- 이벤트 유형과 공개 상태 필터
- 핵심 상태 조회
- 공개 또는 비공개 변경
- 미리보기
- 편집 화면 이동

### 제외 기능

- 이미지 상세 관리
- 방명록 대량 운영
- 고객 소유권 변경
- 이벤트 완전 삭제
- 복잡한 노출 기간 편집
- 다중 선택과 일괄 작업

### 레이아웃

900px 표를 축소하거나 가로 스크롤시키지 않는다. 이벤트명, 유형, 일정, 공개 상태, 고객 연결 상태를 담은 세로 카드 목록을 사용한다.

카드를 선택하면 하단 상세 시트를 연다. 시트에는 미리보기, 공개 상태 변경, 편집 화면 이동만 제공한다. 데스크톱 전용 기능은 숨기고 필요한 경우 `PC에서 관리`라고 안내한다.

## 9. 시각 방향

관리자 화면은 마케팅 페이지가 아니라 반복 작업을 위한 운영 도구로 보이게 한다.

### 줄일 요소

- 큰 소개형 헤더
- 의미가 약한 영문 문구
- 카드 안의 카드
- 모든 영역의 둥근 모서리와 그림자
- 필 형태 버튼과 상태 배지 남용
- 비슷한 설명 문구 반복
- 동작과 연결되지 않는 통계 카드

### 강화할 요소

- 평평한 화면과 명확한 구분선
- 실제 이벤트 데이터 중심의 위계
- 직접적인 한국어 라벨
- 기본 작업 하나에만 강한 강조
- 위험색은 위험 작업에만 사용
- 대표 이미지, 행사일, 공개 상태를 통한 제품 특이성
- 여백과 타이포그래피를 통한 그룹 구분

## 10. 상태와 오류 처리

### 초기 로딩

목록의 구조를 유지하는 스켈레톤을 표시한다. 새로고침 중에는 기존 데이터를 유지하고 갱신 상태만 알린다.

### 조회 오류

- 오류와 빈 목록을 별도 상태로 표시한다.
- 실패한 대상과 가능한 원인을 일반 언어로 설명한다.
- `다시 시도`를 제공한다.
- 캐시 데이터가 있으면 유지하고 최신 정보가 아닐 수 있음을 표시한다.
- 권한 오류와 네트워크 오류를 구분한다.

### 빈 상태

- 등록된 이벤트 없음
- 검색 결과 없음
- 필터 결과 없음
- 특정 유형의 이벤트 없음

검색 또는 필터 결과가 없을 때는 조건 초기화를 제공한다. 이벤트 자체가 없을 때만 생성 동작을 강조한다.

### 변경 상태

- 변경 중인 컨트롤만 비활성화한다.
- 성공하면 화면 상태를 즉시 갱신한다.
- 실패하면 이전 값으로 복구하고 다시 시도 방법을 제공한다.
- 토스트는 직접 닫을 수 있고 보조기술이 읽을 시간을 보장한다.

## 11. 접근성과 키보드

- 검색부터 이벤트 선택과 공개 상태 변경까지 키보드로 완료할 수 있어야 한다.
- 목록 행은 명확한 포커스 표시를 갖는다.
- 상세 패널을 닫으면 선택했던 행으로 포커스를 복구한다.
- 모달과 패널은 Escape로 닫을 수 있다.
- 위험 확인창은 취소 버튼에 최초 포커스를 둔다.
- 페이지 이동 버튼에는 이름을 제공하고 현재 페이지는 `aria-current`로 알린다.
- 로딩, 저장, 성공, 오류는 적절한 라이브 영역으로 알린다.
- 색상 외에 텍스트나 아이콘으로 상태를 함께 전달한다.
- 모바일 핵심 조작은 충분한 터치 크기와 간격을 제공한다.

## 12. 상태와 URL 흐름

- 검색어, 이벤트 유형, 공개 상태, 고객 연결 상태, 정렬, 페이지는 URL query로 유지한다.
- 선택한 이벤트는 별도 query 값으로 표현해 새로고침이나 뒤로 가기 후에도 복원할 수 있게 한다.
- 상세 패널에서 편집 화면으로 이동했다가 돌아오면 기존 목록 조건을 복원한다.
- 공개 상태 변경은 기존 mutation과 권한 검증을 재사용한다.
- API 오류 객체를 화면 상태까지 전달하되 공개 API 구조는 변경하지 않는다.

## 13. 컴포넌트 경계

- `AdminShell`: 공통 상단 바와 업무 영역 내비게이션
- `AdminEventWorkspace`: 이벤트 목록, 선택, URL 상태 조정
- `AdminEventFilters`: 검색, 필터, 정렬
- `AdminEventList`: 데스크톱 목록
- `AdminEventMobileList`: 모바일 카드 목록
- `AdminEventDetailPanel`: 공통 정보와 주요 작업
- `AdminEventCapabilities`: 유형별 관련 관리 기능
- `AdminEventActions`: 편집, 미리보기, 공개 상태 변경
- `AdminQueryState`: 로딩, 오류, 빈 상태

기존 `AdminPageClient.tsx`는 인증, 공통 query 상태, 업무 영역 조정에 집중한다. 큰 `AdminPagesTab.tsx`는 목록, 상세 패널, 작업 컴포넌트로 분리한다. 기존 서비스 함수, API, `StatusBadge`, 오버레이 기반은 동작을 보존하며 필요한 범위에서 재사용한다.

## 14. 적용 순서

1. 공통 관리자 셸과 최상위 내비게이션 정리
2. 이벤트 공통 모델과 유형별 capability 매핑 정리

## 15. 검증 기준

### 기능

- 모든 이벤트 유형이 `전체 유형` 목록에 함께 나타난다.
- 이벤트 유형 필터가 URL에 유지된다.
- 이벤트 선택 후 검색과 목록 상태가 유지된다.
- 편집, 미리보기, 공개 상태 변경이 기존 권한과 API를 사용한다.
- 지원하지 않는 유형별 기능은 표시되지 않는다.
- 조회 오류가 빈 목록으로 표시되지 않는다.

### 반응형

- 모바일에서 데스크톱 표가 노출되지 않는다.
- 가로 스크롤 없이 카드 목록을 사용할 수 있다.
- 모바일 상세 시트에는 승인된 최소 기능만 표시된다.
- 긴 이름, 주소, 다국어 문자열이 레이아웃을 깨뜨리지 않는다.

### 접근성

- 키보드만으로 핵심 흐름을 완료한다.
- 상세 패널 종료 후 포커스가 복귀한다.
- 로딩, 성공, 오류 상태가 보조기술에 전달된다.
- 상태 의미가 색상에만 의존하지 않는다.

### 회귀

- 관리자 인증과 권한 검증이 유지된다.
- 이벤트 생성·편집 위저드 링크가 기존 경로를 사용한다.
- 공개 상태, 고객 연결, 삭제 확인 정책이 약화되지 않는다.
- 공개 이벤트 페이지와 고객 화면의 데이터 동작이 변경되지 않는다.

## 16. 결정 사항

- 추천안인 검색 중심 목록과 상세 패널 구조를 사용한다.
- 관리자 구조는 이벤트 공통 모델을 기준으로 한다.
- 모바일 청첩장은 주요 유형이지만 기본 목록은 전체 이벤트다.
- 이벤트 유형은 최상위 탭이 아니라 필터다.
- 모바일은 조회와 간단한 상태 변경만 지원한다.
- 초기 개선에는 일괄 작업을 포함하지 않는다.
