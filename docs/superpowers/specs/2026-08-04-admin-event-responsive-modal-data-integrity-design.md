# 관리자 이벤트 상세 팝업 및 데이터 연결 개선 설계

## 1. 목표

`/admin/?section=events&tab=pages`의 이벤트 상세 정보를 목록 옆 패널이 아닌 반응형 중앙 팝업으로 제공한다. 데스크톱과 모바일에서 같은 정보와 관리 기능을 제공하고, 관리자 요약 목록에 행사일·장소가 누락되는 데이터 연결 문제와 관련 관리 화면의 선택 이벤트 전달을 함께 점검한다.

## 2. 범위

- 이벤트 상세 사이드 패널을 중앙 팝업으로 전환
- 데스크톱과 모바일에서 동일한 상세 정보·운영 설정·관련 관리·위험 작업 제공
- 관리자 이벤트 요약 API의 행사일·장소 데이터 구성 경로 보완
- 이미지, 추억 페이지, 방명록, 노출 기간, 고객 연결 화면으로 이동할 때 선택 이벤트 유지 확인
- 팝업 접근성, 반응형 레이아웃, 오류·빈 데이터 표현 검증

공개 라우트, API 응답 필드 이름, 인증·인가 정책, 저장 스키마는 변경하지 않는다.

## 3. 선택한 접근

하나의 반응형 중앙 팝업을 모든 화면 크기에서 사용한다.

- 데스크톱: 화면 중앙에 최대 폭 약 760px의 팝업을 배치한다.
- 모바일: 화면 사방에 12~16px 여백을 유지하고, 최대 높이는 `100dvh` 안에 맞춘다.
- 내용이 길면 페이지가 아니라 팝업 본문만 스크롤한다.
- 하단 시트와 전체 화면 전용 변형은 사용하지 않는다.
- 새로운 UI 의존성을 추가하지 않고 기존 관리자 색상·간격·버튼 스타일을 재사용한다.

## 4. 화면 구조와 상호작용

### 목록

이벤트를 선택해도 목록 폭과 열 배치는 바뀌지 않는다. 선택된 행 또는 카드의 강조 상태와 URL의 `event=<slug>`는 유지하여 새로고침과 직접 접근을 지원한다.

### 팝업

팝업은 다음 순서로 구성한다.

1. 이벤트 유형, 이름, 닫기 버튼
2. 행사일, 장소, 공개 주소
3. 편집, 미리보기
4. 공개 상태와 상품·테마 운영 설정
5. 노출 기간과 고객 연결 상태
6. 이미지·추억·방명록·노출 기간·고객 연결 관련 관리
7. 접힌 위험 작업

모바일에서도 위 항목을 숨기지 않는다. 좁은 화면에서는 열 배치만 단일 열로 바꾸고 버튼은 줄바꿈한다.

### 닫기와 포커스

- 닫기 버튼, `Escape`, 배경 클릭으로 닫는다.
- 팝업이 열리면 닫기 버튼으로 포커스를 이동한다.
- 열린 동안 `Tab` 포커스를 팝업 안에 가둔다.
- 팝업이 닫히면 원래 선택한 이벤트 버튼으로 포커스를 복원한다.
- 팝업이 열린 동안 배경 문서 스크롤을 잠근다.
- `role="dialog"`, `aria-modal="true"`, 제목 연결을 모든 화면 크기에 적용한다.

## 5. 데이터 흐름

현재 관리자 요약 서비스는 이벤트 레지스트리 요약과 원본 콘텐츠를 조합하지만, 원본 콘텐츠가 없는 샘플·이관 데이터에서는 `date`와 `venue`가 빈 값으로 남는다. 반면 공개 페이지와 편집 경로에는 샘플 폴백과 정규화된 읽기 경로가 이미 존재한다.

관리자 요약 데이터도 기존 읽기·정규화 규칙을 재사용하도록 구성한다.

1. 이벤트 레지스트리에서 공개 상태, 소유자, 노출 기간, 수정 시각을 읽는다.
2. 저장된 콘텐츠가 있으면 정규화된 콘텐츠를 사용한다.
3. 콘텐츠가 없거나 이관 데이터의 필드가 비어 있고 알려진 샘플 slug라면 기존 샘플 폴백을 적용한다.
4. 최종 페이지 구성에서 `displayName`, `date`, `venue`, 상품 등급, 테마 정보를 관리자 요약으로 변환한다.
5. 실제로 값이 없는 사용자 이벤트만 `일정 미입력`, `장소 미입력`으로 표시한다.

API 응답 구조는 유지하므로 클라이언트 게이트웨이와 기존 mutation은 그대로 사용한다.

## 6. 관련 관리 연결

팝업의 관련 관리 버튼은 기존 query 생성 규칙을 사용한다.

- 이미지·추억·노출 기간: `event=<slug>`를 해당 관리자에 초기 선택값으로 전달
- 방명록: `event=<slug>`와 `commentPageSlug=<slug>`를 함께 전달
- 고객 연결: 선택 이벤트를 고객 관리 화면에 전달

각 관리 화면에서 전달된 slug가 실제 목록에 있을 때만 초기 선택하고, 없으면 기존 기본 상태를 유지한다. 관련 관리 화면으로 이동하면 팝업은 닫힌 상태가 된다.

## 7. 오류와 경계 조건

- 선택 slug가 없으면 팝업을 렌더링하지 않는다.
- 로딩 중이거나 네트워크 오류일 때 존재하지 않는 선택 slug를 성급하게 제거하지 않는다.
- 데이터 로딩 완료 후 slug가 없으면 URL의 `event`를 정리한다.
- 긴 이벤트명과 slug는 줄바꿈하여 팝업 폭을 넘지 않는다.
- 동작 중인 공개 상태·상품·테마 변경 버튼은 기존 비활성화와 진행 문구를 유지한다.
- 체험용 조회 전용 데이터와 위험 작업 제한은 기존 정책을 유지한다.

## 9. 검증

### 자동 검증

- 관리자 이벤트 요약의 저장 콘텐츠·샘플 폴백·실제 빈 데이터 테스트
- 선택 query, 관련 관리 query, 팝업 닫기 키 모델 테스트
- `npm run typecheck:web`
- `npm run lint:web`
- 관련 테스트 묶음
- 변경된 관리자 UI에 Impeccable detector 1회 실행

### 브라우저 검증

인증된 관리자 화면에서 다음을 확인한다.

- 데스크톱에서 팝업을 열어도 목록 폭이 변하지 않음
- 모바일에서도 화면 여백 안의 중앙 팝업으로 표시됨
- 행사일·장소가 저장 데이터 또는 샘플 데이터와 일치함
- 닫기 버튼, 배경, `Escape`, 포커스 순환과 복귀가 동작함
- 편집·미리보기·관련 관리가 올바른 이벤트를 사용함
- 공개 상태 변경과 기존 운영 작업이 회귀하지 않음

브라우저 검증은 데스크톱과 모바일을 한 번의 점검 묶음으로 수행하고, 발견된 문제를 한 차례 수정한 뒤 최종 확인한다.
