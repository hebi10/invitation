# 메인 홈페이지 증거 중심 리디자인 설계

## 목표와 대상

- 메인의 최우선 방문자는 모바일 청첩장 제작을 고민하는 신규 고객이다.
- 방문자는 첫 화면에서 서비스의 제작·공유·운영 범위를 이해하고 제작 문의 또는 실제 샘플 확인으로 이동해야 한다.
- 실제 운영형 서비스라는 차별점을 설명 문구가 아니라 실제 청첩장 화면과 운영 상태 패널로 증명한다.

## 선택한 방향

- 현재의 크림 배경과 짙은 녹색을 유지하는 증거 중심 에디토리얼 구성을 사용한다.
- 히어로 왼쪽에는 가치 제안과 `제작 문의` 주 CTA, `샘플 보기` 보조 CTA를 둔다.
- 히어로 오른쪽에는 실제 샘플 청첩장 화면을 담은 휴대폰 프레임과 공개 상태·방명록·이미지 관리 상태를 보여주는 코드 기반 운영 패널을 배치한다.
- 기존 고객용 `내 청첩장`과 운영자용 `관리자 페이지`는 헤더 유틸리티 링크로 분리한다.
- GPT Image 2는 사용하지 않는다. 제품 증거는 실제 화면으로 제공하고 기존 감성 이미지는 필요한 경우 휴대폰 화면 안의 콘텐츠로만 남긴다.

## 정보 구조와 구성 요소

1. 헤더
   - 좌측 서비스명
   - 우측 `내 청첩장`, `관리자` 유틸리티 링크
2. 히어로
   - 운영형 서비스 포지셔닝을 담은 eyebrow, H1, 짧은 설명
   - 핵심 가치 3개
   - `제작 문의` 주 CTA와 `샘플 보기` 보조 CTA
   - 실제 청첩장 휴대폰 프레임과 운영 상태 패널
3. 서비스 생애주기
   - 정보 입력, 모바일 공유, 운영 관리, 추억 보관의 네 단계를 연결된 흐름으로 표현
   - 동일한 카드 반복을 줄이고 번호와 연결선을 중심으로 구성
4. 포함 기능
   - 확인 가능한 기존 기능만 간결한 목록으로 제공
5. 최종 CTA
   - 운영까지 이어지는 제작 범위를 다시 요약
   - `제작 문의`와 `샘플 보기`를 반복
6. 최소 푸터
   - 기존 고객과 관리자 경로를 다시 제공하되 신규 고객 CTA와 경쟁하지 않도록 낮은 위계로 배치

## 동작과 상태

- 외부 제작 문의만 새 탭으로 열고 새 창임을 접근 가능한 문구로 알린다.
- 내부 샘플과 내 청첩장, 관리자 링크는 같은 탭에서 이동한다.
- 기존 직접 체험 기능은 메인 히어로의 주 CTA에서 제외하되 필요한 서비스 흐름에서 계속 접근 가능하게 유지한다.
- 체험 안내는 Esc로 닫히고, 열릴 때 안내 영역으로 초점이 이동하며, 닫힌 뒤 원래 버튼으로 초점이 돌아간다.
- 체험 안내의 모바일 동작 버튼은 최소 44px 높이를 확보한다.
- 기존 로딩·오류 메시지와 세션 생성 데이터 흐름은 변경하지 않는다.

## 반응형 설계

- 데스크톱은 카피와 제품 증거의 2열 구성을 사용한다.
- 태블릿에서는 제품 패널의 폭을 줄이되 운영 상태가 읽히도록 유지한다.
- 모바일에서는 제목과 CTA 다음에 실제 제품 화면을 즉시 노출한다.
- 모바일 주 CTA는 두 개만 쌓고, 기존 고객·관리자 링크는 헤더 또는 하단의 낮은 위계로 분리한다.
- 모든 주요 터치 대상은 최소 44px, 가로 넘침 없는 390px 레이아웃을 기준으로 한다.

## 검증 기준

- `npm run lint:web`과 `npm run typecheck:web`가 통과해야 한다.
- 데스크톱과 390px 모바일에서 가로 넘침, 텍스트 잘림, CTA 경쟁 여부를 실제 브라우저로 확인한다.
- 내부·외부 링크의 이동 방식이 설계와 일치해야 한다.
- 체험 안내의 열기, Esc 종료, 초점 이동·복귀, 로딩·오류 상태를 확인한다.
- Impeccable detector를 수정 대상에 한 번 실행하고 발견 사항을 검토한다.
