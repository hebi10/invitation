# 고객 소유권 연결 링크 설계

## 1. 목적

관리자가 이벤트 페이지를 먼저 생성한 뒤 고객에게 안전한 연결 링크를 전달하고,
고객이 로그인 또는 회원가입과 이메일 인증을 마치면 해당 이벤트의 소유권을 자동으로
연결해 `/page-wizard/{slug}`에서 즉시 본인 정보를 입력할 수 있게 한다.

현재 관리자 생성 흐름이 로그인한 관리자 UID를 이벤트 `ownerUid`로 자동 기록해
관리자 고객 계정 화면의 미연결 목록에서 제외되는 문제도 함께 해결한다.

## 2. 사용자 흐름

### 관리자

1. 관리자가 이벤트 타입별 위저드에서 새 페이지를 생성한다.
2. 신규 이벤트는 `ownerUid`, `ownerEmail`, `ownerDisplayName`이 모두 비어 있는
   미연결 상태로 저장된다.
3. 관리자 페이지 목록 또는 고객 계정 화면에서 `고객 연결 링크`를 발급한다.
4. 발급 결과에서 링크와 만료일을 확인하고 링크를 복사해 고객에게 전달한다.
5. 같은 이벤트의 링크를 재발급하면 기존 링크는 즉시 사용할 수 없게 된다.

### 고객

1. 고객이 `/connect/{slug}#token={rawToken}` 링크를 연다. URL fragment는 HTTP 요청과
   referrer에 포함되지 않는다.
2. 비로그인 상태에서는 기존 Firebase 이메일 또는 Google 로그인과 회원가입을 제공한다.
3. 이메일/비밀번호 회원가입 계정은 이메일 인증 완료 전까지 연결을 실행하지 않는다.
4. 인증된 계정은 서버에서 연결 토큰을 교환해 이벤트 `ownerUid`를 현재 Firebase UID로
   설정한다.
5. 성공하면 토큰이 포함되지 않은 `/page-wizard/{slug}`로 이동해 즉시 편집한다.

## 3. 접근법 결정

### 채택: 일회용 연결 토큰

- 가입 이메일과 무관하게 관리자가 전달한 링크 소지자를 인증된 Firebase 계정과
  연결할 수 있다.
- 토큰 만료, 재발급 폐기, 단일 사용을 서버에서 일관되게 보장할 수 있다.
- 기존 관리자 소유 이벤트도 고객에게 안전하게 이전할 수 있다.

### 제외: 이메일 사전 지정

- 고객이 다른 이메일 또는 Google 계정으로 가입하면 연결이 실패한다.
- 오타, 이메일 변경, 대소문자 정규화 정책이 소유권 정책에 섞인다.

### 제외: 회원가입 후 관리자 수동 연결

- 현재 구조와 유사하지만 고객이 회원가입 직후 편집할 수 없으므로 목표를 충족하지 못한다.

## 4. 데이터 모델

연결 링크는 이벤트 하위 단일 문서로 관리한다.

```text
events/{eventId}/ownershipInvites/current
```

필드 계약은 다음과 같다.

```ts
interface EventOwnershipInviteRecord {
  tokenHash: string;
  status: 'active' | 'consumed';
  expiresAt: Date;
  createdAt: Date;
  createdByUid: string;
  consumedAt: Date | null;
  consumedByUid: string | null;
}
```

- 원본 토큰은 `crypto.randomBytes(32).toString('base64url')`로 생성한다.
- Firestore에는 SHA-256 해시만 저장하고 원본 토큰은 발급 응답에서 한 번만 반환한다.
- 유효 기간은 발급 시점부터 정확히 7일이다.
- 재발급은 `current` 문서를 새 토큰 해시로 덮어써 이전 링크를 폐기한다.
- 연결 성공 시 같은 트랜잭션에서 `status`, `consumedAt`, `consumedByUid`를 기록한다.
- 운영 데이터 일괄 마이그레이션은 하지 않는다.

## 5. 서버 경계

### 관리자 링크 발급

```text
POST /api/admin/events/{slug}/ownership-invite
```

- `verifyAdminRequest`로 활성 관리자 권한을 검증한다.
- 저장된 이벤트를 slug로 해석한다.
- 이벤트가 미연결이거나 현재 소유자가 활성 관리자일 때만 발급한다.
- 일반 고객 소유 이벤트는 기존 소유권을 보호하기 위해 발급하지 않는다.
- 성공 응답은 원본 연결 URL과 만료 시각을 반환한다.

### 고객 링크 상태 확인

```text
POST /api/connect/events/{slug}/ownership-invite-status
Content-Type: application/json

{ "token": "{rawToken}" }
```

- 고객 인증 API 경계와 분리된 공개 읽기 전용 API이며 소유권을 변경하지 않는다.
- 비로그인 상태에서도 유효한 링크의 페이지명과 `valid`, `expired`, `consumed`, `invalid`,
  `different-owner` 중 안전한 상태만 반환할 수 있다.
- 토큰 원문, 해시, 기존 소유자 UID와 이메일은 반환하지 않는다.
- 상태 확인은 소유권을 변경하지 않는다.

### 고객 링크 교환

```text
POST /api/customer/events/{slug}/ownership-invite
Authorization: Bearer {firebaseIdToken}
Content-Type: application/json

{ "token": "{rawToken}" }
```

- `verifyCustomerRequest`가 검증한 UID와 이메일 인증 상태만 신뢰한다.
- 이메일 미인증 계정은 `403`으로 차단한다.
- Firestore 트랜잭션에서 이벤트와 `ownershipInvites/current`를 함께 읽는다.
- 토큰 해시, `active` 상태, 7일 만료, 현재 이벤트 소유자를 모두 검증한다.
- 이벤트가 미연결이거나 관리자 소유일 때만 현재 고객 UID로 이전한다.
- 이미 같은 고객이 소유한 경우에는 토큰이 유효하면 멱등 성공으로 처리하고 소비 상태를
  기록한다.
- 다른 일반 고객 소유 이벤트는 `409`로 차단한다.
- 이벤트 소유권 변경과 초대 소비 기록은 한 트랜잭션으로 완료한다.

## 6. 관리자 생성 소유권 정책

- 관리자 위저드의 새 페이지 생성만 명시적인 `unassigned` 소유권 모드를 사용한다.
- 기존 페이지 저장은 현재 `ownerUid`를 그대로 보존한다.
- 고객 제작권 API와 모바일 생성 API는 기존처럼 생성 고객 UID를 즉시 연결한다.
- 공용 클라이언트 Repository가 로그인 사용자를 무조건 신규 이벤트 소유자로 지정하지
  않도록 생성 호출에서 소유권 의도를 명시한다.
- 기존 관리자 소유 페이지는 일괄 수정하지 않고 연결 토큰 교환 시 고객에게 이전한다.

## 7. UI 설계

### 관리자 화면

- 기존 관리자 페이지 목록과 고객 계정 화면에 `고객 연결 링크` 작업을 제공한다.
- 기존 버튼, 패널, 토스트, 확인 오버레이 컴포넌트와 관리자 디자인 토큰을 재사용한다.
- 링크 발급 결과에는 이벤트명, 만료일, 링크 복사, 재발급을 표시한다.
- 원본 토큰은 발급 직후 UI 상태에서만 보관하며 새로고침 후 다시 읽어오지 않는다.
- 관리자 생성 이벤트가 미연결인지, 관리자 소유 호환 이벤트인지, 고객 연결 완료인지
  구분되는 상태 문구를 제공한다.

### 고객 연결 화면

- `/connect/{slug}`는 페이지명, 연결 안내, 현재 인증 상태를 한 화면에 표시한다.
- 비로그인 상태는 기존 `FirebaseAuthLoginCard`를 재사용한다.
- 이메일 미인증 상태는 인증 메일 재전송과 인증 상태 새로고침을 제공한다.
- 유효한 인증 사용자는 별도 추가 입력 없이 자동 연결을 시작한다.
- 원본 토큰은 fragment에서 메모리로 읽되 localStorage, sessionStorage, 쿠키에 저장하지 않는다.
- 성공 후 토큰이 URL에 남지 않도록 편집기 URL로 교체 이동한다.
- 만료, 사용 완료, 잘못된 링크, 다른 고객 소유, 서버 오류는 서로 다른 안내 문구로
  표시하고 임의 재시도 또는 관리자 문의가 필요한 경우를 구분한다.

## 8. 보안 및 권한

- 원본 연결 토큰은 Firestore와 서버 로그에 저장하지 않는다. 발급 URL은 query string이
  아닌 fragment를 사용해 HTTP 접근 로그와 referrer에 토큰이 포함되지 않게 한다.
- 연결 링크 발급과 재발급은 관리자 API만 허용한다.
- 소유권 변경은 Firebase ID 토큰과 이메일 인증을 서버에서 검증한 뒤 수행한다.
- 고객 요청의 UID, 이메일, 소유자 필드는 신뢰하지 않는다.
- Firestore Rules는 `ownershipInvites` 클라이언트 직접 읽기와 쓰기를 모두 차단한다.
- 기존 이벤트 소유자는 본인 `ownerUid`를 직접 변경할 수 없다는 현재 규칙을 유지한다.
- 토큰 비교는 해시 값 기준으로 수행하고 오류 응답에는 민감한 상태를 노출하지 않는다.
- 발급과 교환 API에는 기존 요청 제한 패턴을 적용한다.

## 9. 오류 처리

| 상태 | 서버 동작 | 고객 안내 |
| --- | --- | --- |
| 유효 | 인증 후 트랜잭션 연결 | 연결 중 표시 후 편집기로 이동 |
| 이메일 미인증 | `403` | 인증 메일 확인과 상태 새로고침 안내 |
| 만료 | 변경 없이 거부 | 관리자에게 새 링크 요청 |
| 재발급으로 폐기 | 변경 없이 거부 | 최신 링크 사용 안내 |
| 이미 사용 | 변경 없이 거부 | 연결된 계정으로 로그인하거나 관리자 문의 |
| 다른 고객 소유 | `409` | 다른 계정에 연결된 페이지 안내 |
| 이벤트 없음 | `404` | 유효하지 않은 연결 페이지 안내 |
| 서버 오류 | 내부 로그 후 안전한 오류 응답 | 잠시 후 재시도 안내 |

## 10. 테스트와 검증

### 자동 테스트

- 관리자 신규 생성이 로그인 관리자 UID 대신 `ownerUid: null`을 기록한다.
- 기존 이벤트 편집은 현재 고객 또는 관리자 소유권을 보존한다.
- 발급 토큰 원문이 저장되지 않고 7일 만료가 기록된다.
- 재발급 후 이전 토큰은 실패하고 최신 토큰만 성공한다.
- 만료 토큰, 소비 토큰, 잘못된 토큰을 거부한다.
- 미연결 이벤트와 관리자 소유 이벤트를 인증 고객에게 연결한다.
- 다른 일반 고객 소유 이벤트의 이전을 거부한다.
- 이메일 미인증 고객의 교환을 거부한다.
- 동시 교환 중 하나만 성공하도록 트랜잭션 단일 사용을 검증한다.
- 관리자·고객 API 인증 경계와 안전한 오류 응답을 검증한다.
- Firestore Rules가 `ownershipInvites` 직접 접근을 차단하는지 검증한다.

### 브라우저 QA

- 관리자 화면에서 링크 발급, 복사, 재발급 상태를 확인한다.
- 연결 화면에서 로그아웃, 이메일 미인증, 인증 완료 상태를 확인한다.
- 연결 성공 후 토큰 없는 `/page-wizard/{slug}`로 이동하는지 확인한다.
- 데스크톱과 모바일 폭에서 관리자 및 연결 화면의 잘림과 버튼 접근성을 확인한다.

### 회귀 검증

- 관련 신규 테스트
- `npm run test:admin-api-auth`
- `npm run test:customer-api-auth`
- `npm run test:customer-auth-route-policy`
- `npm run test:event-write-paths`
- `npm run test:rules`
- `npm run typecheck:web`
- `npm run lint:web`
- `npm run build`

## 11. 제외 범위

- 운영 Firestore 데이터 일괄 수정 또는 삭제
- 기존 고객 소유 이벤트 자동 이전
- 연결 링크 이메일·문자 자동 발송
- Firebase Auth 이메일 템플릿 변경
- Expo 모바일 앱의 연결 화면 추가
- 공개 이벤트 URL 구조 변경
- 새 외부 의존성 추가
- 커밋, 푸시, 배포

## 12. 완료 기준

1. 관리자 신규 이벤트가 미연결 상태로 생성되어 관리자 화면에서 연결 가능하다.
2. 관리자가 7일 만료·1회용 연결 링크를 발급하고 재발급할 수 있다.
3. 고객이 링크에서 가입 또는 로그인과 이메일 인증을 완료하면 자동으로 소유권이 연결된다.
4. 연결 완료 후 고객이 바로 해당 페이지 편집기로 이동한다.
5. 기존 관리자 소유 이벤트는 링크를 통해 고객에게 이전할 수 있다.
6. 다른 고객 소유 이벤트와 직접 Firestore 접근은 차단된다.
7. 관련 자동 테스트, 타입체크, 린트, 빌드와 브라우저 QA가 완료된다.
