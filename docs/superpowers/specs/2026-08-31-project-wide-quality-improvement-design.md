# 프로젝트 전체 품질 개선 설계

## 목표

프로젝트 평가에서 확인된 배포 차단 문제와 핵심 UX 문제를 해결하면서 기존 공개 라우트, 저장 스키마, 인증·인가 경계, 테마별 시각 언어를 보존한다.

## 성공 기준

- 웹 런타임에서 신뢰할 수 없는 이미지 입력을 처리하는 직접 의존성의 알려진 고위험 취약점을 제거한다.
- `npm run check`, `npm test`, `npm run test:architecture`, `npm run test:security`, `npm run test:emulator`, `npm run build`가 모두 통과한다.
- 신규 페이지 위저드는 편집 전 경고를 표시하지 않고 실제 입력과 저장 결과에 따라 단계 상태를 계산한다.
- 체험 관리자와 실제 관리자 화면이 동일한 운영 UI 토큰을 사용한다.
- 테마 선택은 각 테마의 분위기를 선택 전에 비교할 수 있게 한다.
- 관리자 필터는 자주 쓰는 조건과 상세 조건을 구분하되 기존 검색 결과와 쿼리 의미를 바꾸지 않는다.
- 공개 청첩장은 선택 기능 활성화 여부와 무관하게 일관된 마무리 메시지를 제공한다.
- README의 테마와 검증 설명이 실제 코드와 일치한다.

## 접근 방식

### 1. 배포 안정성 우선

직접 런타임 의존성은 현재 메이저 라인을 가능한 한 유지한다. Next.js와 Firebase 계열은 호환 가능한 패치 버전으로 올리고, `sharp`는 보안 수정 버전인 0.35 이상으로 올린 뒤 이미지 업로드·리사이즈 계약 테스트와 실제 빌드를 검증한다. 모바일 의존성은 Expo SDK 55 호환 범위 안에서 패치 업데이트하고, SDK 메이저 업그레이드는 이번 범위에 포함하지 않는다.

GYEOL 테마 추가 이후 뒤처진 미리보기 계약을 실제 테마 레지스트리를 기준으로 갱신한다. 보안 정적 가드는 문자열 출현 횟수 대신 허용된 저장소와 쓰기·삭제 행위를 구분하도록 바꾼다. 에뮬레이터 테스트는 각 테스트가 자신이 사용하는 컬렉션을 시작과 종료 시 정리해 실행 순서에 의존하지 않게 한다.

### 2. 위저드 상태 모델 개선

위저드 상태를 `최초 진입`, `편집됨`, `저장 중`, `저장 성공`, `저장 실패`로 구분한다. 최초 진입에는 경고를 노출하지 않고, 사용자가 값을 변경한 뒤에만 미저장 상태를 표시한다. 단계 완료 여부는 단순 방문 여부가 아니라 해당 단계의 필수 데이터 충족 여부로 계산한다. 기존 저장 API와 이벤트 스키마는 변경하지 않는다.

테마 선택 단계에는 기존 렌더러나 프로젝트 자산을 재사용한 미리보기 카드와 핵심 분위기 설명을 제공한다. 별도 이미지 생성이나 새 테마 추가는 하지 않는다.

### 3. 관리자 정보 밀도 개선

항상 필요한 검색·상태 필터·초기화는 기본 영역에 유지한다. 유형, 공개 상태, 고객, 정렬, 페이지 크기처럼 빈도가 낮은 조건은 접근 가능한 상세 필터 영역으로 묶는다. 필터 값과 서버 요청 구조는 유지해 데이터 동작에는 영향을 주지 않는다.

체험 관리자 레이아웃에는 실제 관리자와 같은 `data-operation-ui` 경계를 추가한다. 체험 세션 및 접근 게이트 동작은 변경하지 않는다.

### 4. 공개 청첩장 마무리 보장

갤러리와 방명록 등 선택 섹션이 비활성화되어도 마지막에 신랑·신부 또는 주최자의 감사 문구가 나타나도록 공통 마무리 섹션을 둔다. 테마 렌더러는 기존 타이포그래피와 색상 토큰을 사용해 각 테마의 독립적인 디자인을 유지한다.

### 5. 유지보수 경계와 문서

이번 변경과 직접 관련된 대형 파일에서만 순수 상태 계산 함수, 필터 UI, 마무리 섹션처럼 독립적으로 테스트할 수 있는 단위를 추출한다. 전체 렌더러나 위저드의 전면 재구성은 하지 않는다. README의 테마 목록, 기능 설명, 검증 명령을 실제 레지스트리와 `package.json`에 맞춘다.

## 오류 처리와 호환성

- 의존성 업데이트로 타입 또는 빌드 오류가 발생하면 API 사용부를 최소 수정하고 공개 인터페이스는 유지한다.
- 업로드 최적화 실패 시 기존 오류 응답과 원본 보호 정책을 유지한다.
- 위저드 저장 실패는 기존 재시도 경로를 유지하며 편집 내용이 저장된 것으로 표시하지 않는다.
- 필터 상세 영역을 닫아도 선택된 조건은 유지하고, 초기화 동작만 모든 조건을 제거한다.
- 공개 청첩장의 기존 URL, 메타데이터, 공유 링크 동작은 변경하지 않는다.

## 검증 전략

행동 변경은 실패하는 계약 테스트를 먼저 추가하거나 수정한 뒤 최소 구현으로 통과시킨다. 단위·계약 테스트 후 웹과 모바일 타입 검사, 전체 빠른 테스트, 보안·아키텍처·에뮬레이터 테스트, 프로덕션 빌드 순으로 실행한다. 마지막에는 홈, 체험 관리자, 신규 위저드, 샘플 공개 청첩장을 데스크톱과 모바일 뷰포트에서 확인한다.

## 범위 제외

- Firebase 저장 스키마나 인증 정책 변경
- 신규 테마 또는 신규 비즈니스 기능 추가
- Expo SDK 메이저 업그레이드
- 전체 코드베이스 리팩터링
- 운영 데이터 변경, 푸시, 배포
