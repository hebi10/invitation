# INV-FIX-02-H — 모바일 임시 업로드 정리 안전성

기존 앱의 동일 slug 경로만 확인하던 DELETE는 이미 저장된 대표/갤러리/공유/추억 페이지 사진도 지정할 수 있었다. 신규 서버 업로드의 세 변형 파일에 인증된 서버 세션 식별자의 해시를 기록하며 기존 업로드 응답 및 토큰은 유지한다. 정리 API는 현재 서버 세션/이벤트/소유권, 전체 변형 파일 경로, 업로드 세션 메타데이터, 저장된 참조를 확인하고 재조회한 뒤 Storage generation precondition으로 삭제한다. 예전 미연결 객체나 권한/참조/메타데이터 불확실 시 보존하고 409로 안내한다. 누락된 객체는 멱등성 있게 구분한다.

제한: Firestore와 Storage 간 원자적 트랜잭션은 아니다. 참조 재확인 이후 다른 쓰기가 발생할 가능성 및 타 이벤트/구형 참조에 대한 운영 검증은 여전히 필요하다. 운영 파일을 정리하거나 토큰을 폐기하지 않는다. 신규 업로드 메타데이터에 해시만 추가되며, 이전 고객 사진·API 응답 호환과 신규 서버 코드 CI/실기기 정리 검증이 필요하다.
