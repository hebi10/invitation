# UI-R03 — 모던형(classic-r) 모바일 청첩장 리뉴얼

기준: 2026-11-11. 선행 스택 PR #83(UI-R00) → #84(UI-R01) → #85(UI-R02) 이후 작업.

## 구현 범위
- WeddingBase.tsx: 모던형의 기존 3개 바로가기(예식 안내/오시는 길/사진 보기)에 선형 아이콘을 노출. 사진이 없다면 사진 링크를 생성하지 않음.
- WeddingBase.module.css: classic-r 전용 간격, 3열 바로가기, 인트로 후 초대 문구 폭, 블랙 예식 안내 정보 패널, 흰색 텍스트, 날짜/시간·장소 위계, 펼침/달력 컨트롤 대비, 하단 링크.
- WeddingCover.module.css: .editorial 범위의 영문 라벨/이름/날짜/장소 간격·크기 조정, 320px 줄바꿈.
- 기존 모던형 번호형 섹션 가상 요소와 테마 구조는 유지하며 새로운 번호/영문 라벨을 중복 삽입하지 않음.

## 유지·제외
- 고객의 weddingCover.textPosition과 focusX/focusY 및 실제 사진, 사용자 데이터, 예식 날짜/장소.
- 갤러리 와이드 슬라이드, 기존 원본 확대, 접힘 연락처·계좌·달력, 지도 및 방명록.
- 다른 4개 테마(simple/romantic/gyeol/emotional), vow 및 제작·관리 화면, Firestore/Storage, 결제·Play/Firebase 설정 변경 없음.
- 인위적 꽃 장식, 3D, 그림자, 그라데이션, 추가 애니메이션 금지.

## 검증 게이트
1. PR #83/#84/#85 CI와 캡처를 확인하고 순차 병합. 이 PR은 선행 #85 브랜치를 base로 사용.
2. ESLint, TypeScript, 단위/회귀 테스트, Next.js Build 및 CSS Modules 컴파일.

4. 기존 섹션 번호와 영문 라벨 중복/잘림 여부 및 블랙 예식 패널의 대비, 달력 열기/닫기·ICS, 갤러리 사진 유무·확대, 지도/방명록/계좌 확인.
5. 실제 Android/iOS 물리 기기 검증 및 운영 도메인은 별도. 고객 데이터·실결제 요청 금지.
