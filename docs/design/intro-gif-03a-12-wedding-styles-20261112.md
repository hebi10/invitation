# Invitation — INTRO-GIF-03-A · 웨딩 중심 12종 인트로 콘셉트 확정

기준: 2026-11-12 · 목적: 시안/실제 자산 제작 전 확정된 동작·스타일 명세 · 상태: 기획 확정, 이미지/GIF 미제작
관련: Issue #98 · Draft PR #100~#104 · 기존 디자인 시스템(Quiet Invitation 1-A/1-B/2-B/UI-07-B)

## 1. 최종 방향
- 고객은 **12종 중 1종 또는 ‘사용 안 함’**을 직접 선택합니다. 미리보기와 저장은 분리합니다. GIF 재생 2초가 본문 자동 진입을 의미하지 않습니다.
- **심플 3 / 감성 3 / 화려 3 / 캐릭터 3** 네 그룹을 동등한 정보 위계로 배치합니다. 구형 9종이 너무 비슷하다는 피드백을 반영하여 색·도형·움직임의 차이를 실물 카드에서 즉시 구별할 수 있게 합니다.
- **intro-01은 기존 GIF 자산·ID를 보존**합니다. 현행 임시 9종 제작 브랜치(`feat/intro-gif-03-assets-catalog-20261112`)의 intro-02~10은 **폐기 대상 설계**이며 고객 공개/운영에 사용하지 않습니다. 새 기준은 01~12로 재정의하고 확정된 포스터와 GIF 파일이 검증되기 전에는 신규 ID를 활성화하지 않습니다.
- **적용 범위 제안 B를 구현 기준으로 채택**: 01~06은 모든 활성 행사에서 공통 사용 가능한 중성 문구, 07~12는 웨딩 전용 장식/커플. 기존 웹·Android가 유형 필터 없이 카탈로그를 노출하므로 후속 03-D에서 카탈로그 타입별 필터와 서버 검증을 별도 구현해야 합니다. 그 전에는 전체 활성화 금지.
- 등록된 ID는 삭제/재사용 금지. 이미 반영된 `introStyle` 레거시 값은 새 저장값으로 강제 변경하지 않고 유지합니다.

## 2. 공통 제작·UI 기준
- 캔버스: 480×600px(4:5), 8프레임×250ms = 2,000ms, `loop` 미설정, 초기–전개–완성의 읽히는 2초.
- 타이밍: F1=0~250ms, F2=250~500ms, F3=500~750ms, F4=750~1000ms, F5=1000~1250ms, F6=1250~1500ms, F7=1500~1750ms, F8=1750~2000ms. 마지막 프레임이 포스터와 시각적으로 일치해야 합니다.
- 색채: 베이스 #FFFFFF/#FAFAFA, 텍스트 #262626~#343434. 심플·감성은 중성 회색 중심. 화려는 블러시 로즈(#D9A9B1)·샴페인 골드(#B69A64)를 **포인트에만** 사용. 아이보리/크림/민트/짙은 녹색 일괄 적용 금지.
- 연출: 평면 일러스트/선형, 명조 주제목 + 고딕 보조 서체. 3D, 가짜 사진, 강한 그림자·그라디언트·과도한 이펙트, 글리터 잔광 금지. 화려 그룹도 시선 집중용 1개 메인 연출만.
- 텍스트: 공통군은 ‘초대합니다’ 중심, 웨딩군은 영어 `WEDDING INVITATION` 보조 가능. 고객 실명·결혼 날짜·개인 사진·장소를 GIF 자산에 하드코딩하지 않음. 수동 입력/실시간 합성 요구는 별도 기능으로 취급.
- 접근성: 포스터와 GIF 모두 내용 이해 가능, 모션 감소 시 포스터 대체, 빈 화면·404 시 원래 본문 이동 가능, 키보드 Escape/Tab·건너뛰기, 44~48px 컨트롤. 반복 재생·자동 본문 이동 없음.
- 성능 예산(제안, 03-C 검증에서 결정): GIF 심플 ≤100KB, 감성 ≤180KB, 화려 ≤350KB, 캐릭터 ≤450KB 목표; 600KB 이상은 QA 불합격·재압축. WebP 포스터 각각 ≤50KB 목표. 모든 GIF 한꺼번에 다운로드 금지.
- 포스터: GIF 최종 프레임의 480×600 WebP + 필요 시 PNG, 정적 목록에는 WebP만 지연 로드, 미리보기에서 선택한 단일 GIF만 재생. 실제 등록 파일 SHA-256/크기/재생시간/프레임 수 manifest 기록.

## 5. 캐릭터 아트디렉션(10~12 공통)
- 2D 플랫 일러스트, **같은 신랑·신부 캐릭터 기본 모델**로 3종 장면을 제작해 시리즈 일관성 확보. 정면·측면·손동작 표정/의상/선 두께 비례 통일.
- 작은 화면에서 몸짓이 읽혀야 하므로 손잡기·행진·인사 각각 동작 구별. 커플은 화면 중앙 60% 범위 이내, 머리–몸 비율 약 1:4, 의상은 단색 블랙/차콜 수트·밝은 드레스(디테일 과장 금지).
- 얼굴·피부·헤어는 불필요하게 특정 개인이나 인종을 암시하지 않는 범용 도안. 기존 실사용자/유명인 사진을 복제하지 않음. 개별 커플 맞춤 설정은 별도 기능이므로 기본 GIF에는 삽입하지 않음.
- 결혼식 인트로임을 알아볼 수 있도록 작은 꽃/리본/단정한 하트 중 최대 1종만 장면에 추가. 3D 렌더/피규어/가짜 화보 질감 배제.

## 6. 고객 선택 화면·데이터 구조 확장
- 선택 화면: 그룹 탭(심플·감성·화려·캐릭터) + 모든 스타일 보기, 포스터 2열(모바일)/3열(PC), 이름·약 2초·미리보기·선택 버튼. 그룹별 3개. 현재 적용/미저장/저장 완료 구분. ‘사용 안 함’은 그룹 외 공통 상단 행.
- 데이터 모델(후속 03-D): `id`, `group`, `sortOrder`, `label`, `description`, `supportedEventTypes`, `gifSrc`, `posterSrc`, `durationMs`, `sha256`, `active`. `introPresetId`는 영구 ID만 저장; 조회·미리보기·서버 저장에서 이벤트 권한 및 등록 상태 확인.
- **불변 보존**: `introStyle=none/light/cinema/envelope`, 기존 고객 선택, 이벤트 유료 상품과 공개 권한, 음악·사진·가족/방명록. 저장값 검증에서 미지원 ID를 임의 `none`으로 변환하지 않음.
- 미리보기는 선택·자동 저장과 무관; 공개 하객 화면은 저장된 ID의 GIF 1개만 표시. 2초 완료 자체가 이동 트리거가 아니며 ‘초대장 보기/건너뛰기’ 버튼 동작 유지.
- 캐릭터 3종은 웨딩에서만 노출. 공통 행사에서 07~12 저장 요청을 받은 경우 서버에서 거부하고 기존 선택값을 보존. 이벤트 변경/구형 Android로 편집 시 기존 ID 무단 삭제 금지.
- 포스터는 각 카드 지연 로드, GIF는 미리보기 호출 시에만 다운로드. WebP/PNG 미등록·SHA 불일치·2000ms 규격 실패한 ID는 `active`로 등록 금지.

## 7. 이전 9종 브랜치 교체 규칙
- 이전 임시 브랜치 `feat/intro-gif-03-assets-catalog-20261112`는 02=봉투, 03=종이, ... 10=타이틀로 등록돼 있어 새 12종 번호와 **충돌**합니다. 브랜치 자체를 main이나 최신 02-D에 병합하지 않으며, 생성 스크립트 `scripts/generate-intro-gif-03.py`·구형 카탈로그 해시를 신규 명세에 복사하지 않습니다.

- `intro-01`만 기존 파일·등록 ID를 보존합니다. 02~12는 새 디자인 시안 승인 및 검증 뒤 등록하며, 코드의 기존 10종 가정 테스트와 리소스 로더를 12종으로 갱신합니다.
