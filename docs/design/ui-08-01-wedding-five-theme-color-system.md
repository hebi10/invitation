# UI-08-01 — 공개 청첩장 5종 컬러 팔레트 확정

## 범위와 판단
- 기준: 현재 `main` 2233a183, `DESIGN.md`의 표시명 및 `WeddingBase.module.css`의 실제 테마 키.
- **기본형 `simple`, 모던형 `classic-r`, 포토형 `romantic`, 클래식형 `gyeol`, 내추럴형 `emotional`** 다섯 종류만 적용한다.
- 사용자가 확인한 2026-11-11 이미지 시안의 공통 원칙은 **테마 내 색상 통일**, **그린의 임의 혼입 제거**, **각 디자인 고유의 개성 유지**다. 생성 시안의 색은 확정 원본이 아니라 시각 참고이며, 아래 값은 실제 코드의 후기 단계 선언과 조화되도록 정한 실행 기준이다.
- 이 단계는 **색상 설계 확정**이다. 고객 화면의 실제 CSS 수정·운영 배포·기존 사용자 데이터 변경은 다음 작업에서 한다.

## 디자인 성격과 금지 사항

1. **기본형 · Ivory Paper** — 따뜻한 아이보리·웜그레이·차콜. 이번 카드/접힘/예식 안내 참고 시안에서 초록이 등장했다면 제거. 장식적 금색은 기본 액션 컬러로 쓰지 않음.
2. **모던형 · Black Editorial** — 순백·검정·중립 회색. 식물·핑크·베이지 장식이 기본 버튼과 폼에 유입되지 않도록 방지.
3. **포토형 · Warm Photograph** — 따뜻한 종이색·브라운 그림자 없는 무드·차콜 CTA. 사진 색조가 UI 텍스트나 액션 컬러를 임의 변경하지 않도록 방지.
4. **클래식형 · Champagne Letter** — 크림·브라운·샴페인 톤의 선. 샴페인은 선/장식에 제한하고 가독성 낮은 연금색 본문 금지.
5. **내추럴형 · Garden Sage** — 유일하게 **세이지/올리브 녹색을 브랜드 포인트**로 사용. 예식 안내 배경·방명록 CTA·달력/아코디언도 동 계열로 연결.

## 현재 코드와 차이(구현 후속)

- `WeddingBase.module.css`: 각 테마에 **중복된 토큰 선언이 존재**하고 뒤쪽 블록이 앞쪽 값을 재정의한다. 기본형 `paperSoft`는 앞쪽 `#f0ede7`, 뒤쪽 `#f4f4f4`로 상충한다. 신규 기준은 `#F0EDE7`이다.
- 같은 파일에서 모던형·포토형·클래식형·내추럴형 역시 후기 선언이 초기 토큰과 다르다. **UI-08-02에서 최종값 단일화**가 필요하다.
- `weddingThemes.ts`의 `WEDDING_SHARE_PALETTES`는 본문 토큰과 다른 값이 있으므로 UI-08-02에서 동일 원천으로 연결한다.
- 달력·방명록·연락처·공유·인트로·사진 컴포넌트에 하드코딩된 테마 외 색상은 UI-08-02 이후 검수·교체 대상이다. 이 파일 작성만으로 해당 UI가 변경되지는 않는다.
- GIF/애니메이션 파일의 자체 배경색은 선택된 테마의 토큰을 따라야 한다. 공용 고정색 GIF로 5종을 덮어쓰지 않는다.
